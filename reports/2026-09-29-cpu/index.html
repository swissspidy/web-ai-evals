Built-in AI vs in-page models, same prompts, same browser

Four task suites run through Chrome's built-in Gemini Nano and Gemma 4 (behind a Chrome flag), Chrome's Summarizer and Translator APIs, and a Transformers.js model, all inside a real Chrome tab driven by Playwright. Every number below comes from 4 runs on the machines listed here.

  1. On the same machine, Gemma 4 trails Gemini Nano on sentiment, and the two are level on summarization, extraction and translation (Apple M4 Pro, Chrome 156.0.8078.12): sentiment accuracy 0.867 vs 0.940 (−0.073, 95% CI −0.107 to −0.040, 300 examples); summary ROUGE-L 0.318 vs 0.319 (−0.001, 95% CI −0.027 to +0.026, 60 examples); extraction field accuracy 0.977 vs 0.970 (+0.007, 95% CI −0.008 to +0.020, 150 examples); translation chrF 0.804 vs 0.823 (−0.019, 95% CI −0.040 to +0.001, 200 examples). The sentiment gap is in the hard examples: 0.743 vs 0.879 on the 140 hard ones, 0.975 vs 0.994 on the other 160. Gemini Nano answers sooner (time to first token 136 ms vs 866 ms for Gemma 4 on sentiment), but Gemma 4 streams faster once it starts (106 vs 55 tokens/s on summaries). Gemma 4 needs a GPU: on the CPU-only machine, Chrome 154 downloaded it but crashed every time it created a session.
  2. Gemma 3 1B in the page (Transformers.js on WebGPU) is faster than Gemini Nano on every suite on the Apple M4 Pro, but scores below Gemini Nano on sentiment, extraction and translation: sentiment accuracy 0.717 vs 0.940 (95% CI of the difference −0.270 to −0.173) at 89 ms vs 151 ms per example; summary ROUGE-L 0.304 vs 0.319 (95% CI of the difference −0.036 to +0.008) at 835 ms vs 1.4 s per example; extraction field accuracy 0.898 vs 0.970 (95% CI of the difference −0.095 to −0.050) at 733 ms vs 1.1 s per example; translation chrF 0.676 vs 0.823 (95% CI of the difference −0.173 to −0.121) at 215 ms vs 372 ms per example. The page downloads this q4f16 model itself, while Gemini Nano ships with Chrome.
  3. On WebLLM, the same Gemma 3 1B model scores below its Transformers.js run on sentiment, summarization, extraction and translation on the Apple M4 Pro, though it answers faster: sentiment accuracy 0.637 vs 0.717 (95% CI of the difference −0.120 to −0.040) at 60 ms vs 89 ms per example; summary ROUGE-L 0.051 vs 0.304 (95% CI of the difference −0.282 to −0.222) at 83 ms vs 835 ms per example; extraction field accuracy 0.788 vs 0.898 (95% CI of the difference −0.152 to −0.070) at 600 ms vs 733 ms per example; translation chrF 0.515 vs 0.676 (95% CI of the difference −0.197 to −0.128) at 174 ms vs 215 ms per example. WebLLM returned empty answers for 46 of 60 summarization examples and 5 of 200 translation examples; it reports 0 output tokens for them, so the model ends its answer at once. This WebLLM build only loads with {"sliding_window_size":-1} (WebLLM 0.2.85's model record and the model's config disagree), so the gap may come from that setting rather than from the runtime itself.
  4. Gemini Nano is 4–9× faster on the Apple M4 Pro's GPU than on the CPU-only machine. Median time per example on the examples both runs share: 147 ms vs 1.3 s on sentiment, 1.2 s vs 5.9 s on summarization, 1.0 s vs 4.0 s on extraction, 339 ms vs 1.8 s on translation. Its scores differ too (translation chrF 0.907 vs 0.860 on the same 20 sentences), but Chrome ships different Nano builds for GPU and CPU and the two machines ran different Chrome versions, so the score gap isn't down to the hardware alone.
  5. On CPU, Gemini Nano matches or beats a 0.5B in-page model on every suite: sentiment accuracy 0.900 vs 0.767, extraction field accuracy 1.000 vs 1.000, translation chrF 0.860 vs 0.496.
  6. It is also faster. Median time to first token 1.3 s vs 2.9 s on sentiment; a summary takes 5.9 s vs 53 s. Chrome's native CPU inference outruns ONNX Runtime Web's Wasm backend by a wide margin.
  7. Chrome's Summarizer API ignores format: "plain-text" on this build, and misbehaves with it. In tl;dr mode it returned a Markdown news article every time (12 of 12), averaging 242 words for ~100-word inputs, with invented placeholders such as “[Region Name]”. In key-points mode, 7 of 12 answers were bullet lists of questions about the article. Key points in Markdown format, the API default, looked right in a spot check. The Prompt API with a plain instruction scores ROUGE-L 0.319 against 0.143 for the Summarizer.
  8. Chrome's Translator API matches Gemini Nano on translation at a fraction of the latency: chrF 0.854 vs 0.860, with the exact reference phrasing in 50% vs 35% of sentences, at 20 ms vs 1.8 s per sentence. On first use it fails until Chrome has installed its translation runtime and language pack, with errors that don't say so; the runner retries until the install finishes.
  9. Gemma 3's q4 ONNX builds don't run on Transformers.js Wasm (ONNX Runtime Web lacks GatherBlockQuantized on Wasm), and WebLLM on a software WebGPU adapter loses the device. Browser AI on machines without a GPU is, in practice, built-in AI or a small model on Wasm.

How it was measured

  • One browser, one backend, one example at a time; the model loads once per cell, from a persistent profile.
  • Timing happens inside the page with performance.now(). TTFT is the first streamed text; latency is the median wall time per example after the first.
  • Greedy decoding where the API allows it (temperature 0, 256 new tokens max). Web pages cannot set the Prompt API's temperature.
  • Scores average all examples; errors and timeouts count as 0.

What is missing
